## User-facing AI Video Studio requirements
Add a clearly separate "AI Video" creation mode alongside the existing source/edit workflow. Do not route AI-generated footage through ShortsEditor, because ShortsEditor automatically performs podcast transcript analysis when a source video is loaded.

The new mode must support:
- Multiple named character profiles.
- Multiple reference image uploads per character, with previews, remove/reorder, type/size validation and clear identity labels.
- Character appearance notes and wardrobe/continuity notes.
- Main creative prompt.
- Exact requested final duration in seconds, 10–300 seconds.
- Aspect ratios 9:16, 16:9, 1:1 and 4:3.
- Resolution selection, limited to verified model/output support.
- Language selection.
- Timecoded scene list. Each scene has start/end seconds, visual action, camera framing/movement, location, characters present, dialogue/audio notes and optional negative prompt.
- Add, remove, reorder and edit scenes.
- Validate no negative/zero-length scenes, no overlaps, no unintended gaps and exact total duration. Allow intentional gaps only when explicitly requested.
- Display model/runtime capability warnings before queueing.
- Show real per-scene generation progress, retry/regenerate and cancellation where the worker supports them.
- Preview and download the final MP4.

## Generation architecture
The app frontend must not run GPU inference. Netlify/Express web handlers must not pretend to be GPU workers. Keep the generation engine behind a server-side provider interface and run inference in a separate private GPU worker.

Use WanGP as the first provider candidate, but treat the existing Gentleman Studio WanGP plugin as a prototype/reference, not a production-ready HTTP API. Inspect the actual WanGP version installed on the worker and its API documentation before implementing the adapter.

Required provider interface (adapt names to project conventions):
- discoverCapabilities()
- createJob(validatedTimeline, characterReferences, renderSettings)
- getJob(jobId)
- cancelJob(jobId)
- getOutput(jobId)

Before enabling a model, query WanGP's live model metadata/schema. Check that the selected model actually supports video output, image inputs, reference-image role(s), requested aspect/resolution and requested clip length. Use model-declared reference modes/flags and settings only. Do not guess field names or use a model merely because its label sounds compatible.

For each scene:
- Generate a short clip within the selected model's verified frame/duration limits.
- Pass only the relevant character reference images using the model's declared image reference mechanism (for example WanGP image_refs and its supported reference mode, only if the selected model schema declares it).
- Keep character IDs, facial appearance, hair, wardrobe, age-appropriate styling, location, lighting and visual style consistent.
- Use previous-scene final frames as continuity references only if the selected model supports that input role.
- Store source prompts, actual settings, model ID/version, scene output paths and errors in a manifest.
- Do not claim perfect face consistency; surface model limitations honestly.

Assemble scene clips in exact timeline order with FFmpeg on the worker. Normalize frame rate, dimensions, pixel format, codecs and audio before concatenation. Preserve scene timing. Generate a final MP4 and run ffprobe plus a full decode validation. Do not overwrite an existing output. Return a real output file or authenticated, short-lived download URL.

Five minutes means a five-minute final assembly of model-supported short clips. It does not mean one continuous five-minute model inference. Never silently shorten the requested final duration.

## Existing publishing handoff — critical
When generation succeeds and final MP4 validation passes:
1. Fetch the MP4 as a Blob/File in the browser through the authenticated app backend.
2. Create an object URL for preview and construct the existing ExportedShortResult shape:
   - url: object URL
   - blob: actual MP4 Blob
   - filename: generated .mp4 filename
   - mimeType: actual video/mp4
   - durationSec: measured final duration from ffprobe/manifest
   - suggestedTitle: optional generated title
3. Pass that result to the same App-level exportedShort state used by ShortsEditor.
4. Navigate to the existing publish stage and pass the result to the existing YouTubePublishPanel unchanged.
5. The existing publisher must remain responsible for channel verification, confirmation, metadata, privacy/scheduling, resumable upload and success/error display.
6. Revoke object URLs when replaced or when the component unmounts, without revoking the URL while the publisher still needs it.
7. If the worker output is unavailable, invalid, expired or too large to retrieve safely, show a real error; never fake an ExportedShortResult.

Do not automatically publish. User must review the generated MP4 and explicitly confirm upload through the existing confirmation modal. Keep private/unlisted as the safe test path.

## API and data contracts
